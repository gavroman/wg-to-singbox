# VPN-профили для sing-box

CLI получает подключения из wg-easy и 3x-ui, собирает профиль sing-box и публикует его в S3 вместе со страницей подключения и QR-кодом.

Требования: Node.js 24.22.1, wg-easy 14, 3x-ui 3.11 и существующий S3-бакет. Конфигурации проверяются ядром sing-box 1.14.4.

## Настройка

Команды выполняются из каталога `sing-box-configs`.

```bash
npm ci
cp -n configs/vpn.example.json configs/vpn.private.json
chmod 600 configs/vpn.private.json
```

Заполните адреса панелей, доступы и настройки S3 в приватном JSON. Его разделы:

| Раздел | Назначение |
|---|---|
| `panels` | Адреса и доступы к wg-easy и 3x-ui |
| `connections` | Подключения, которые войдут в профиль |
| `s3` | Endpoint, регион, бакет и ключи S3 |
| `routing.rulesUrl` | HTTPS URL общего файла rules |
| `dns` | Адрес и TLS-имя DNS-over-HTTPS сервера |
| `urltest` | Необязательные параметры автоматического выбора подключения |
| `network.reservedSubnets` | Необязательный список занятых сетей для проверки WG-подсетей |

Путь к файлу задаётся через `--config` или `VPN_CONFIG` в окружении / `.env`:

```dotenv
VPN_CONFIG=./configs/vpn.private.json
```

`--config` имеет приоритет. Относительные пути разрешаются от рабочего каталога. Приватные конфиги исключены из Git.

Ключи `connections` — уникальные имена подключений в sing-box. Поле `panel` ссылается на ключ из `panels`. Для 3x-ui имена начинаются с `3x-` и используются как примечания inbound. К имени можно добавить флаг страны через пробел. Отсутствующие inbound создаются автоматически; существующие проверяются по имени и параметрам. Для WG нужно указать свободную подсеть, для VLESS REALITY — target и serverNames. Порты должны быть свободны на соответствующем сервере.

## Создание и обновление профиля

```bash
npm run config:check -- --config configs/vpn.private.json
npm run panels:check -- --config configs/vpn.private.json
npm run provision -- --config configs/vpn.private.json --name phone
```

Первая проверка работает без сети. Вторая читает состояние панелей и ничего не меняет.

`provision` находит или создаёт клиента на панелях, получает выбранные подключения и публикует профиль. Имя `phone` нормализуется в `sf-phone`. Повторный запуск с тем же именем обновляет профиль по прежнему URL. Для запрета перезаписи объектов S3 добавьте `--create-only`.

Команда возвращает `pageUrl`, `profileUrl`, диплинк и пути к локальным файлам. Откройте `pageUrl` для импорта в приложение. После обновления на сервере обновите Remote Profile в приложении.

## Загрузка отредактированного JSON

```bash
npm run upload -- \
  --config configs/vpn.private.json \
  --input ./sing-box.json \
  --connections ./connections.json \
  --name phone
```

`upload` публикует готовый JSON без пересборки и обращения к панелям. Мапка подключений должна соответствовать JSON. Если `--connections` не указан, мапка читается из S3.

## Остальные команды

Аргументы npm-команд передаются после `--`. Все команды с настройками принимают `--config`. Справка: `npm run <команда> -- --help`.

| Команда | Назначение |
|---|---|
| `profiles:list` | Показать опубликованные профили и состав подключений |
| `profiles:update --all` | Пересобрать все опубликованные профили по выбранному конфигу |
| `wg --name phone [--connection <имя>]` | Сохранить локальную мапку WG-подключений, без публикации |
| `convert --input <файл> [--output sing-box.json]` | Локально преобразовать мапку подключений, WG .conf или файл с одной URI |
| `configs:pull` | Скачать профили и rules из S3 в `artifacts` |
| `rules:update [--input <файл>]` | Опубликовать rules и обновить их версию в профилях |
| `connect --url <https-url> --name phone` | Создать диплинк и QR; приватный конфиг не требуется |

`--rules` у provision, convert и profiles:update переопределяет `routing.rulesUrl`. Повторная сборка сохраняет `?v` прежнего управляемого URL rules. `--client-id` у provision/wg выбирает клиента единственной используемой панели wg-easy; его имя должно совпадать с именем профиля.

`convert --output` принимает имя файла рядом с input; перезапись самого input запрещена. У standalone URI/.conf имя подключения задаётся через `--name`, по умолчанию `sf-vpn`.

## Режимы и DNS

При одном подключении групп нет. При нескольких появляются selector `vpn` и urltest `auto` со всеми подключениями. Начальный выбор в `vpn` — `auto`.

В приложении доступны два режима:

- **По правилам** — совпавший с rules трафик идёт через VPN, остальной напрямую.
- **Все через VPN** — весь пользовательский трафик идёт через выбранное VPN-подключение.

DNS учитывает тот же режим и общий rule-set. В полном режиме запросы идут к VPN DNS. В режиме по правилам VPN DNS выбирается по rules, иначе используется системный DNS. Служебные запросы для подключения к VPN, загрузки rules и urltest используют независимый системный DNS.

Для одного WG с DNS в исходнике используется этот сервер. Для остальных профилей — DoH из раздела `dns`, с IPv4-only разрешением. Неподдерживаемый IPv6-трафик, который должен идти через VPN, отклоняется.

Настройки urltest по умолчанию: URL `https://www.gstatic.com/generate_204`, интервал `1m`, tolerance `80` мс. Их можно переопределить одноимёнными полями раздела `urltest`.

## Файлы

В S3 профиль лежит в `profiles/sf-<name>/`:

- `sing-box.json` — конфигурация sing-box;
- `connections.json` — мапка имя подключения → URI;
- `index.html`, `qr.png` — страница подключения и QR;
- `data.json` — имя профиля и ссылки на опубликованные файлы.

Локальная копия — `artifacts/profiles/<имя>--<hex>/`. Суффикс различает имена с разным регистром. Старые `wireguard.conf` сохраняются; новые профили используют `connections.json`.

`configs:pull` полностью заменяет локальный `artifacts` после успешного скачивания. `rules:update` без `--input` читает `artifacts/rules/vpn_rules.json`. Команда `wg` сохраняет результат в `exports/<имя>--<hex>/connections.json`. Каталоги `artifacts` и `exports` исключены из Git, конфиги сохраняются с правами `0600`.

Опубликованные профили и мапки содержат доступы VPN и доступны по публичным URL. Серверные записи автоматически не удаляются. При частичном сбое публикации команда сообщает путь к рабочим файлам для восстановления.

## Проверки

```bash
npm run typecheck
npm test
SING_BOX_BINARY=/absolute/path/to/sing-box npm run test:sing-box
```

Обычные тесты используют локальные mocks. Для их HTTPS-сервера нужен `openssl` в `PATH`: тесты генерируют временные TLS-ключ и сертификат, читают их в память и сразу удаляют файлы. Проверка ядром подтверждает корректность конфигурации, но не доступность VPN-сервера.
